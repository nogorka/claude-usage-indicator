# Два аккаунта Claude в одной панели

Дата: 2026-09-10. Статус: дизайн утверждён к планированию.

## Задача

На машине две подписки Claude. Нужно видеть состояние обеих разом — расход и время
сброса — и запускать сессию в нужном аккаунте кнопкой, без логина-логаута.
Автоматического переключения нет и не будет: решение принимает человек.

Порог достоверности задан владелицей: проценты достаточно правдоподобных оценок,
**время сброса обязательно**.

### Готово, когда

1. В панели одновременно видны оба профиля: метка, связывающее окно, процент.
2. Профиль, в котором сейчас нет сессии, помечен как несвежий, и в меню указано,
   на какой момент его данные.
3. Время сброса каждого окна показано для обоих профилей и не зависит от свежести.
4. Окно, срок которого истёк, не показывает старый процент.
5. Меню трея содержит по пункту запуска на каждый найденный на диске профиль.
6. Один профиль на диске — состав и порядок блоков бара те же, что до изменений;
   единственное расхождение — правило просроченного окна из требования 4, которое
   действует при любом числе профилей.
7. Полный прогон тестов зелёный, покрытие новых модулей от 80%.

## Что установлено фактами, а не предположением

Проверено чтением кода и прямым экспериментом 2026-09-10.

**Лимиты приходят push-ом, доставать их не надо.** Хук статуслайна читает JSON со
stdin: `rate_limits.five_hour`, `rate_limits.seven_day`, `rate_limits.model_scoped[]`
(`bin/claude-statusline.sh:137-145`). Обращений к `.claude.json`, `~/.claude` или
`CLAUDE_CONFIG_DIR` в скрипте нет — grep даёт ноль. Данные появляются как побочный
эффект живой сессии.

**`CLAUDE_CONFIG_DIR` разделяет профили физически.** `claude doctor` под чужим
каталогом конфига создал внутри него собственный `.claude.json` и `backups/`, а общий
`$HOME/.claude.json` не тронул (mtime до и после совпадает). Там же сообщил
«Not signed in to claude.ai» при залогиненном рабочем аккаунте — значит
`.credentials.json` тоже per-profile.

**Асимметрия имени конфига.** Без переменной конфиг лежит в `$HOME/.claude.json`;
внутри `~/.claude/` файла `.claude.json` не существует. С переменной —
в `$CLAUDE_CONFIG_DIR/.claude.json`. Это влияет на визард заведения профиля,
на индикатор — нет.

**Понятия профиля в коде сейчас нет.** `grep -rn "CLAUDE_CONFIG_DIR\|profile\|account"`
по всему репозиторию — 0 совпадений.

**Хук ставится один раз на оба профиля.** `statusLine` в `settings.json` указывает на
`/home/nogorka/.local/bin/claude-statusline.sh`. Второй профиль получает `settings.json`
симлинком на общий, поэтому хук там срабатывает без отдельной установки.

## Почему push, а не поллер

Активный опрос API лимитов третьей стороной запрещён правилами Anthropic: страница
`code.claude.com/docs/en/legal-and-compliance` прямо запрещает сторонним разработчикам
собирать, хранить и посредничать в передаче учётных данных Claude.ai, а Consumer Terms
запрещают автоматический доступ к сервисам без API-ключа. Push-схема токена не касается
вовсе: индикатор читает файл, который официальный клиент сам ему положил.

Побочное следствие — узел теории `secret-delivery-to-process` («права токена сужаются
до операции, а не до сервиса») к этому дизайну неприменим: секрета в контуре нет.

Цена схемы: профиль, в котором нет сессии, не обновляется. Это принято осознанно и
отражено в требованиях 2 и 3.

## Архитектура

```
claude (профиль A)  --stdin JSON--> claude-statusline.sh --> ~/.local/state/claude-usage/default.json
claude (профиль B)  --stdin JSON--> claude-statusline.sh --> ~/.local/state/claude-usage/personal.json
                                                                        |
                                          claude_usage_indicator (демон) читает каталог целиком
                                                                        |
                                                        бар панели + меню трея + окно «Подробнее»
```

Один хук-скрипт обслуживает оба профиля, различая их по окружению своего процесса.
Один демон, один AppIndicator, один таймер — как сейчас.

### Идентификация профиля

Идентификатор выводится **только** из `CLAUDE_CONFIG_DIR`:

- не задана либо указывает на `$HOME/.claude` → `default`
- иначе: `basename` разрешённого пути, срезаются ведущие точки и префикс `claude-`,
  остальное приводится к `[a-z0-9_-]`, прочее заменяется дефисом
  (`~/.claude-personal` → `personal`)

Почему не отдельная переменная имени: забытая переменная означала бы два аккаунта в
одном файле и молча врущую панель. Вывод из `CLAUDE_CONFIG_DIR` этого случая не имеет
по построению — эта переменная и есть то, что разделяет аккаунты.

Ограничение: два разных каталога с одинаковым basename дают один идентификатор
(`~/a/.claude` и `~/b/.claude`). Для схемы «профиль на аккаунт в `$HOME`» недостижимо;
в спеке зафиксировано как известная граница.

Метка для человека — необязательная `CLAUDE_USAGE_PROFILE_LABEL` («раб», «личн»),
её выставляют пункты меню запуска. Не выставлена — в баре стоит идентификатор.
Худший исход строго косметический: файл и разделение аккаунтов от метки не зависят.

### Файлы состояния

Сейчас один `~/.local/state/claude-usage/latest.json`; имя зашито литералом в обоих
реализациях (`bin/claude-statusline.sh:196`, `src/claude_usage_indicator/state.py:76-77`).

Станет `~/.local/state/claude-usage/<id>.json` — по файлу на профиль. Запись остаётся
атомарной как сейчас: `mkdir -p -m 0700` → `mktemp` в целевом каталоге → `chmod 0600`
→ `printf` → `mv -f` (`bin/claude-statusline.sh:203-216`).

`CLAUDE_USAGE_STATE` (полный путь к файлу) сохраняет сегодняшнюю семантику и приоритет:
это файл, в который пишет **данная** сессия. На нём держатся bash-тесты.

### Схема состояния

Версия поднимается до 2, добавляется один блок:

```json
{
  "schema": 2,
  "profile": {"id": "personal", "label": "личн", "config_dir": "/home/nogorka/.claude-personal"},
  "updated_epoch": 1788547623,
  "limits": {"five_hour": {"percent": 42.3, "resets_epoch": 1788550200}},
  "order": ["five_hour"],
  "extra_usage": null
}
```

Остальные поля не меняются.

**Совместимость.** Читатель принимает обе версии. Файл со `schema: 1` (нет блока
`profile`) трактуется как профиль `default` с меткой `default`. Поэтому старый
`latest.json` после апгрейда отрисуется правильно сам собой.

**Дедупликация.** Индикатор читает все `*.json` каталога состояния и группирует по
`profile.id`. Два файла с одним идентификатором (переходный период: старый
`latest.json` рядом с новым `default.json`) — берётся тот, у кого `updated_epoch`
больше. Файл, который не разбирается или не проходит валидацию схемы, не роняет
чтение: он пропускается. Профиля у такого файла нет по определению, поэтому его имя
уходит не в `problem` снимка, а в отдельный список проблем чтения каталога, который
показывается одной строкой в меню и в окне «Подробнее». Остальные профили
рендерятся как обычно.

`install.sh` дополнительно удаляет осиротевший `latest.json`, если рядом уже лежит
`default.json`. Это уборка, а не условие корректности.

### Рендер

**Один профиль на диске — поведение бара байт в байт сегодняшнее.** Это отдельное
требование, а не следствие: сегодняшний опыт не должен измениться, пока второй
аккаунт не заведён.

**Два и больше.** Каждый профиль отдаёт в бар одно **связывающее** окно — то, где
процент выше:

```
раб 5h ▓▓░░ 42% · личн 7d ▓▓▓░ 61%*
```

Причина: четыре и более блоков в панель GNOME не помещаются. Полная разбивка по всем
окнам, включая `model:*`, и времена сброса — в меню и в окне «Подробнее», секцией на
профиль.

Порядок профилей стабильный: `default` первым, дальше по алфавиту идентификатора.
Порядок «свежий первым» отвергнут: метки в панели, меняющиеся местами, нечитаемы.

Звёздочка — данные несвежие (порог `is_stale`, сегодня 3600 с), в меню строкой
«данные на 09.09 17:20». Тревожный статус индикатора (`ATTENTION`) поднимается, если
порог 80% достигнут **в любом** профиле.

### Просроченные окна

`bar.py:114-125`: при `delta_s <= 0` `format_reset` роняет хвост «in Nh Mm», но
`panel_label` продолжает показывать старый процент. Для одного активного аккаунта это
редкий случай; для спящего профиля — норма, и 87% на экране становятся заведомо
неверным числом.

Правило: окно с `resets_epoch <= now` считается сброшенным. В баре и меню показывается
`0%` с пометкой оценки; строка сброса — «окно сброшено 09.09 17:20, следующее начнётся
с первой сессии».

Это оценка, а не факт: аккаунтом могли пользоваться с телефона или с claude.ai, и тогда
реальный расход больше нуля. Порог достоверности задан владелицей как «правдоподобно»,
и оценка ему отвечает, а старое число — нет. Следующее время сброса не вычисляется:
пятичасовое окно стартует от первой сессии, а не по расписанию, и вычисленное значение
было бы выдумкой.

### Переключатель

Профили для меню находятся по диску, а не по файлам состояния: у нового профиля файла
состояния ещё нет, а кнопка нужна сразу. Правило поиска: каталоги `$HOME/.claude` и
`$HOME/.claude-*`, внутри которых существует `.credentials.json`. Проверяется
существование, содержимое не читается никогда.

На каждый найденный профиль в меню добавляется пункт «Открыть Claude — `<метка>`»,
поднимающий `gnome-terminal` с нужными `CLAUDE_CONFIG_DIR` и
`CLAUDE_USAGE_PROFILE_LABEL`. Терминал в системе один — `gnome-terminal`.

Глобального «переключения» не происходит и не предполагается: `CLAUDE_CONFIG_DIR`
действует на запускаемый процесс, обе сессии могут идти одновременно.

## Границы: чего в этой работе нет

- Никаких обращений к `api.anthropic.com` и вообще к сети из индикатора.
- Никакого чтения `.credentials.json`, `.claude.json` и любых токенов.
- Никакого автоматического переключения аккаунтов и никакой подмены учётных данных.
- Никакой установки сторонних инструментов (`cswap`, `claude_ai_usage_widget`
  рассмотрены и отвергнуты по правилам Anthropic).
- Заведение второго профиля кодом не делается: это живой секрет и необратимое
  действие, поставляется отдельным визардом для исполнения человеком.

## Принятые допущения и их цена

**MCP-логины переносятся в личный профиль целиком** (решение владелицы 2026-09-10,
вопреки рекомендации не переносить). Цена: рабочие доступы к linear, slack, notion,
github окажутся в личном аккаунте, а токены будут лежать в двух каталогах вместо
одного — компрометация любого даёт тот же набор. Записано как осознанный выбор.

**Общий харнесс раздаётся симлинками** (решение владелицы 2026-09-10). Симлинками во
второй профиль уходят `settings.json`, `CLAUDE.md`, `hooks/`, `skills/`, `agents/`,
`commands/`, `scripts/`, `rules/`, `theory/`, `templates/`, `plugins/`, `mcp-configs/`,
`ecc/`. Персональными остаются `.credentials.json`, `.claude.json`, `projects/`,
`todos/`, `shell-snapshots/`, `history.jsonl`, логи и кэши. Цена: поломка
`settings.json` ломается сразу в обоих профилях. Выигрыш: во втором профиле
действуют deny-правила и `block-lavish-share.py`, без чего профиль был бы небезопасен.

**Спящий профиль показывает последнее известное с явной отметкой времени**, а не
скрывается. Владелица выбрала этот вариант из трёх.

## Риски

| Риск | Следствие | Что делаем |
|---|---|---|
| `patch-settings.py` пишет через временный файл и `replace` | Запуск против симлинка `~/.claude-personal/settings.json` заменит симлинк обычным файлом и профили разъедутся | Скрипт отказывается работать, если цель — симлинк, с внятным текстом ошибки |
| Claude Code перезаписывает `settings.json` атомарно | Симлинк может быть заменён файлом извне нашего кода | Не чинится этой работой; фиксируется как известный риск схемы симлинков |
| Каталог состояния содержит мусорный `*.json` | Чтение могло бы упасть целиком | Файл пропускается, имя уходит в список проблем чтения каталога, остальные профили рендерятся |
| Одинаковый basename у двух каталогов конфига | Один идентификатор на два аккаунта | Зафиксировано как граница схемы |

## Тестирование

Стек прежний: stdlib `unittest` плюс два bash-набора со своим раннером
(`tests/test_statusline.sh`, `tests/test_install_uninstall.sh`). Сейчас 116 питоновских
тестовых функций и 22 фикстуры.

Обязательно покрывается:

- вывод идентификатора: переменная не задана, `$HOME/.claude`, `~/.claude-personal`,
  путь с мусорными символами, путь с завершающим слэшем;
- чтение схемы 1 без блока `profile` как профиля `default`;
- дедупликация двух файлов с одним идентификатором по `updated_epoch`;
- битый и нечитаемый файл в каталоге не ломает чтение остальных;
- бар при одном профиле на непросроченных данных совпадает с сегодняшним посимвольно
  (regression-фикстура); отдельным тестом — что просроченное окно меняет его и здесь;
- бар при двух профилях: выбор связывающего окна, порядок, отметка несвежести;
- просроченное окно: `0%`, текст «сброшено», отсутствие выдуманного следующего сброса;
- поиск профилей на диске: каталог без `.credentials.json` не считается профилем;
- `patch-settings.py` отказывается писать в симлинк.

Прогон перед ревью и перед финишем — полный:

```
PYTHONPATH=src /usr/bin/python3 -m unittest discover -s tests -p 'test_*.py'
bash tests/test_statusline.sh
bash tests/test_install_uninstall.sh
```
