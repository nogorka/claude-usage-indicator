# План: индикатор лимитов Claude Code в панели GNOME

## Цель

Показывать остаток лимитов Claude Code (окна 5 часов и 7 дней) в верхней панели GNOME
на Ubuntu 24.04 (GNOME Shell 46, Wayland), с быстрым доступом к деталям.

## Жёсткие ограничения

Нарушение любого пункта делает работу непринятой.

1. **Ноль сети.** Ни одного исходящего запроса ни из одного файла репозитория.
2. **Ноль доступа к секретам.** Ни один файл не читает `~/.claude/.credentials.json`
   и не обращается к переменной `CLAUDE_CODE_OAUTH_TOKEN`.
3. **Ноль новых зависимостей.** Только системный `/usr/bin/python3` 3.12, stdlib,
   `gi` (PyGObject, уже стоит), `jq` (уже стоит), `systemd --user`.
   Тесты на stdlib `unittest`, не на pytest.
4. **Ничего не копируется в систему.** Установка это симлинки и один юнит.

## Единственный источник данных

Хук `statusLine` Claude Code получает на stdin JSON сессии. В нём есть **необязательный**
блок `rate_limits`. Схема ниже вытащена из бандла Claude Code (doc-блок статус-строки
плюс zod-схема), а не выдумана:

```
rate_limits?: {                      // только у подписчиков и только после первого ответа API
  five_hour?:            { used_percentage: number, resets_at: number }   // epoch-секунды
  seven_day?:            { used_percentage: number, resets_at: number }
  seven_day_opus?:       то же
  seven_day_sonnet?:     то же
  seven_day_oauth_apps?: то же
  model_scoped?: [ { display_name: string, utilization: number|null, resets_at: string|null } ]  // ISO-8601
  extra_usage?: { is_enabled, monthly_limit, used_credits, utilization, currency }
}
```

Любое поле может быть null. Поля `percentage` не существует, оно называется
`used_percentage`. Окна `spend_limit` в статус-строке нет вовсе, ближайшее реальное
понятие это `extra_usage`.

**Per-model окна.** Отдельного окна под Fable в схеме нет: лимиты, привязанные к
конкретной модели, приезжают массивом `model_scoped`, где `display_name` это серверная
метка (в самой схеме приведён пример «Fable»). Поэтому поддерживается весь массив как
класс, а не одно захардкоженное имя: сколько окон пришло, столько баров и показано.

Блок приходит только после первого запроса модели в сессии. Его может не быть вовсе.
Локальные транскрипты в `~/.claude/projects` лимитов **не содержат**, проверено.

## Ш0. Схема файла состояния (зафиксирована)

Путь: `~/.local/state/claude-usage/latest.json`, права `0600`.
Это единственный шов между хуком и демоном.

```json
{
  "schema": 1,
  "updated_epoch": 1788547623,
  "limits": {
    "five_hour":   {"percent": 42.3, "resets_epoch": 1788550200},
    "seven_day":   {"percent": 55.0, "resets_epoch": 1788700000},
    "model:fable": {"percent": 21.0, "resets_epoch": 1788700000, "label": "Fable"}
  },
  "order": ["five_hour", "seven_day", "model:fable"],
  "extra_usage": {"percent": 31.0, "used_credits": 12.4, "monthly_limit": 40.0, "currency": "USD"}
}
```

Правила:

- `percent` берётся из `used_percentage` для фиксированных окон и из `utilization`
  для элементов `model_scoped`. Пишется как есть, без округления.
- `resets_epoch` всегда целые epoch-секунды; для `model_scoped` ISO-строка переводится
  в epoch. Ключ отсутствует, если перевод не удался или времени не было.
- Ключ элемента `model_scoped`: `model:` плюс `display_name` в нижнем регистре,
  пробелы в дефисы, всё кроме `a-z0-9._-` выбрасывается. Элемент без `display_name`
  или с `utilization: null` пропускается.
- `label` есть только у ключей `model:*`, это исходный `display_name`.
- `order` задаёт порядок отображения: `five_hour`, `seven_day`, затем элементы
  `model_scoped` в серверном порядке. Содержит только реально существующие ключи.
- `seven_day_opus`, `seven_day_sonnet`, `seven_day_oauth_apps` не переносятся:
  они дублируют то, что сервер кладёт в `model_scoped`.
- `extra_usage` пишется только при числовом `utilization`, в панель не попадает никогда.
- `limits` может быть пустым объектом: сессия ещё не сделала ни одного запроса модели.
- `updated_epoch` пишется всегда, это unix-время записи файла.
- Запись атомарная: временный файл в том же каталоге плюс `mv` поверх целевого.
  Демон не должен уметь прочитать половину файла.

## Критерии приёмки

Готово, когда выполнено всё:

1. В верхней панели GNOME постоянно видны 5h и 7d плюс по бару на каждое per-model
   окно из `model_scoped` (Fable в том числе): текстовый бар из блоков плюс процент.
2. Выше 80 процентов в любом из окон метка краснеет.
3. Клик по метке открывает меню: оба окна с баром и временем сброса, лимит трат,
   возраст данных, флажок автозапуска, пункт «Подробнее», выход.
4. Пункт «Подробнее» открывает окно GTK с настоящими графическими барами.
5. Индикатор поднимается сам после перезагрузки, руками ничего запускать не надо.
6. При закрытом Claude Code панель честно показывает, что данные устарели.
7. Сессия без блока `rate_limits` не ломает ни хук, ни демон.
   Битый, пустой и отсутствующий файл состояния тоже.
8. Грепом по репозиторию подтверждается: ни одного сетевого вызова, ни одного упоминания
   credentials и токенов.

## Внешний вид

Панель (текстовый бар, 8 ячеек, символы `▓` и `░`):

```
5h ▓▓▓░░░░░ 42% · 7d ▓▓▓▓░░░░ 55% · Fable ▓▓░░░░░░ 21%
```

Метки: `five_hour` это `5h`, `seven_day` это `7d`, per-model окно печатается своим
`label`. Порядок из `order`.

Меню:

```
5 ЧАСОВ
  ▓▓▓░░░░░ 42%
  сброс в 23:10, через 1 ч 23 м
─────────────────────────────
7 ДНЕЙ
  ▓▓▓▓░░░░ 55%
  сброс в пятницу, 06.09 в 09:00
─────────────────────────────
FABLE
  ▓▓░░░░░░ 21%
  сброс в понедельник, 08.09 в 03:00
─────────────────────────────
Доп. расход               31%
─────────────────────────────
данные от 21:45, 2 минуты назад
✓ Запускать при входе в систему
Подробнее…
─────────────────────────────
Выход
```

Когда данных нет вообще: в панели `Claude: нет данных`, меню объясняет,
что цифры появятся после первого запроса в Claude Code.

Когда данные старше часа: метка приглушается, в меню возраст данных.


Волна 2: Task 3 и Task 4 параллельно.

## Шаги

### Task 1. Хук statusLine

`bin/claude-statusline.sh`, bash плюс jq.

- Читает JSON со stdin один раз.
- Достаёт `rate_limits.five_hour`, `rate_limits.seven_day`, элементы
  `rate_limits.model_scoped` и `rate_limits.extra_usage` в схему Ш0.
  Отсутствующее окно просто не попадает в `limits`.
- Пишет `~/.local/state/claude-usage/latest.json` атомарно, права 0600,
  каталог создаётся при необходимости.
- Печатает в stdout строку статуса для Claude Code: тот же бар, что в панели.
- Никогда не падает и не пишет в stderr на нормальных входах: Claude Code показывает
  вывод хука пользователю. Битый вход это пустая строка и нулевой код возврата.

Установка блока в `~/.claude/settings.json` делается скриптом `install.sh` (Task 3),
руками файл не правим.

### Task 2. Демон-индикатор

`src/claude_usage_indicator/`, системный python3.

- `state.py`: чтение и разбор файла состояния. Чистые функции, без GTK.
  Возвращает нормализованное состояние либо явный признак «данных нет».
  Битый JSON, пустой файл, отсутствующий файл, чужая версия схемы: не исключение,
  а признак «данных нет» с причиной.
- `bar.py`: чистые функции рендера. Бар из 8 блоков по проценту, текст метки панели,
  правило покраснения на 80, форматирование возраста данных и времени сброса по-русски.
- `indicator.py`: AyatanaAppIndicator3, метка, меню, таймер опроса раз в 10 секунд.
- `__main__.py`: точка входа.

TDD: сначала тесты на `state.py` и `bar.py` (unittest), потом реализация.
GTK-часть тестами не покрывается, проверяется в Task 5.

Границы: функция до 50 строк, файл до 800, вложенность до 4.
Комментарии на русском, идентификаторы английские. Комментарий объясняет «почему».

### Task 3. Установка и автозапуск

- `systemd/claude-usage-indicator.service`: юнит `--user`, `Restart=on-failure`,
  `PYTHONPATH` на `src` репозитория, ExecStart через `/usr/bin/python3 -m claude_usage_indicator`.
- `install.sh`: симлинк хука в `~/.local/bin`, установка юнита, `systemctl --user enable --now`,
  добавление блока `statusLine` в `~/.claude/settings.json` без затирания остальных ключей
  (правка через python3 и json, с резервной копией; если `statusLine` уже занят, скрипт
  останавливается и говорит об этом, а не перезаписывает).
- `uninstall.sh`: снимает всё то же самое.
- Оба скрипта идемпотентны.

### Task 4. Окно «Подробнее»

`src/claude_usage_indicator/window.py`.

- Окно GTK3 с `Gtk.LevelBar` или `Gtk.ProgressBar` по каждому окну лимита, включая per-model окна из `model_scoped`.
- Время сброса, доп. расход (если есть), возраст данных.
- Открывается пунктом меню, повторный вызов поднимает существующее окно, а не плодит новые.
- Закрытие окна не гасит демон.

### Task 5. Сквозной прогон

Реальная проверка на машине, с доказательствами в отчёт:

- запустить демон, увидеть метку в панели;
- прогнать хук с фикстурой, где есть `rate_limits`, увидеть обновление панели;
- прогнать с фикстурой без `rate_limits`, убедиться, что ничего не сломалось;
- открыть меню и окно;
- состарить `updated_epoch`, увидеть приглушение;
- `systemctl --user restart`, убедиться, что поднимается.

### Task 6. Гарды

- Полный прогон тестов.
- Грепы: `curl|wget|urllib|requests|http|socket` и `credentials|OAUTH|token` по репозиторию.
- Права файла состояния 0600.
- README с описанием, установкой, удалением и честным ограничением про свежесть данных.

## Честное ограничение

Цифры обновляются, только пока Claude Code запущен, и только после первого запроса модели
в сессии. Закрыт Claude Code: панель показывает последнее известное значение и его возраст.
Свежесть 24/7 достижима только через OAuth-эндпоинт с токеном, а это ровно тот риск,
ради устранения которого всё и делается.
